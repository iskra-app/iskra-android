# Перенос с iOS

Эталон — `iskra-app/iskra`, ветка `dev`. Переносится **коммит**, а не пересказ: читай настоящий diff,
сообщение коммита и комментарии в затронутых файлах — они объясняют *почему*.

Аргументы: `$ARGUMENTS`

## 1. Где iOS и что переносить

Работа обычно идёт в worktree (`.claude/worktrees/…`), поэтому `../iskra` ненадёжен. iOS-репозиторий
лежит рядом с основным чекаутом этого:

```sh
IOS="${ISKRA_IOS:-$(cd "$(git rev-parse --path-format=absolute --git-common-dir)/../.." && pwd)/iskra}"
git -C "$IOS" fetch -q origin dev 2>/dev/null; git -C "$IOS" rev-parse --verify origin/dev
```

Читай iOS только **по коммиту** (`git -C "$IOS" show <sha>`, `git -C "$IOS" show <sha>:<path>`), не
рабочее дерево: там может лежать чужая незаконченная работа.

- Аргумент — хэш или диапазон: проверь, что каждый коммит есть в `origin/dev`
  (`git -C "$IOS" merge-base --is-ancestor <sha> origin/dev`). Нет — остановись и скажи.
- Без аргумента: последний перенесённый — самый свежий трейлер `iOS-Commit` в `dev` этого репозитория:
  `git log origin/dev --format='%(trailers:key=iOS-Commit,valueonly)' | grep -m1 .`.
  Диапазон — `<он>..origin/dev` в iOS, без мерж-коммитов (`--no-merges --reverse`). Трейлеров ещё нет —
  спроси, с какого коммита начинать.

## 2. Разобрать каждый коммит

Для каждого: `git -C "$IOS" show --stat --format=%B <sha>`, затем diff, затем затронутые файлы
**целиком** на этом коммите. Отнеси коммит к одному из трёх:

- **переносится** — экран, раскладка, поведение, тексты, логика стора/ленты, общая для платформ;
- **частично** — смысл общий, но часть — обход особенности Apple;
- **только Apple** — AppKit/UIKit/`NSTextView`, особенности SwiftUI-раскладки, `Package.swift`,
  `Apps/project.yml`, `release.sh`, подпись, App Group, Keychain. Такой не переносится, но
  **учитывается** (трейлер в шаге 6) и называется в отчёте с причиной.

Android — это прежде всего телефон и планшет: эталон для него — iPhone и iPad. Коммиты «Mac: …» чаще
всего «только Apple»; переносится из них то, что про широкую раскладку планшета или про поведение,
а не про механику macOS.

Если исправление — обход бага Apple, не копируй обход: проверь, есть ли такой же баг здесь.

## 3. Найти своё место

Ищи аналог по именам типов, ключам строк, текстам и комментариям. Соответствие слоёв:

| iOS | Android |
|---|---|
| `Sources/IskraFeatures/**View.swift` | `:features` (Compose-экраны) |
| `Sources/IskraDesign`, `Theme.swift`, `AccentTheme.swift` | `:design` (`Theme.kt`, `Chrome.kt`) |
| сторы, `TimelineStore`, работа с SDK | `:core` (наверх — только value-типы) |
| `*.lproj/Localizable.strings` | `res/values*/strings.xml` — **только через синхронизацию** |

Правило модулей (`checkModuleRules`) не нарушать: Compose в `:core` нельзя, Matrix в `:design` нельзя.

## 4. Перенести

**Как у iOS, близко к один-в-один:** состав экрана и порядок элементов, иерархия, отступы и размеры
(в значениях из `Theme`, кратных 4), состояния (пусто, загрузка, ошибка, отключено), что по чему
нажимается и куда ведёт, тексты, тайминги анимаций, где они важны для смысла.

**По-своему, в стиле этого репозитория:** компоненты Material 3 и свои из `:design`
(`PrimaryActionButton`, `SecondaryActionButton`, …), роли `MaterialTheme.colorScheme`, системная
навигация и жесты Android. Не рисуй iOS-контролы на Compose.

Инварианты из `CLAUDE.md` действуют как всегда: ни одной строки в composable, семь языков полные,
каждое ожидание SDK — `withTimeLimit`, ничего лишнего в логах.

Новые строки **не пиши руками** — они уже добавлены в iOS. Привези их:

```sh
scripts/sync-from-ios.sh "$IOS" <последний переносимый sha>
```

Строки, нужные только Android, — `values*/strings_android.xml`, на всех семи языках.

## 5. Проверить

`./gradlew check`. Затронут SDK — ещё `:core:connectedDebugAndroidTest`, если есть эмулятор.
Пункт `ROADMAP.md`, который этим закрывается, отметь в том же коммите.

## 6. Закоммитить

По-русски, в стиле iOS-репозитория: тот же заголовок, что у iOS (без префикса «Mac:»; свой префикс,
если он нужен), тело — что и почему, и чем перенос отличается от iOS, если отличается. Обычно один
коммит на один iOS-коммит; мелочь можно объединять.

В каждом коммите — трейлер **на каждый покрытый iOS-коммит**, включая пропущенные как «только Apple»
(их перечисли в теле: «Не перенесено: <sha> — <почему>»). Если в диапазоне переносить нечего вовсе —
пустой коммит `git commit --allow-empty` с этими трейлерами, чтобы следующий запуск не начинал заново.

```sh
git commit -s -m "<заголовок>" -m "<тело>" --trailer "iOS-Commit: <полный sha>" [--trailer …]
```

Не пушь и не сливай в `dev` — это делает автор после просмотра.

## 7. Отчитаться

Коротко:
- таблица: iOS-коммит → перенесено / частично / не перенесено, и почему;
- где раскладка или поведение разошлись с iOS и зачем;
- что посмотреть глазами на устройстве;
- ветка, на которой лежит работа.
